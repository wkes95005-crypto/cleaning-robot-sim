# 賣場清潔機器人調度模擬器

機器學習期中提案（第 8 組）的模擬平台：一台中控台（你的電腦）調度 2 台掃地機、1 台拖地機、1 台障礙排除機（機械手臂），在 24 m × 16 m 的賣場地圖上分工合作。

只用 Python 標準函式庫，不需安裝任何套件。

```bash
python3 run.py                  # 開啟儀表板 http://127.0.0.1:8780
python3 run.py --headless 1500  # 不開畫面，跑 1500 tick 後印出日誌與統計
python3 -m unittest discover -s tests -t .
```

## 系統架構

```
 機器人（每台各自執行）                          中控台（筆電）
+------------------------------+   無線（模擬延遲）   +-----------------------------------+
| 麥克風 → 機上 ASR → 文字      | ---- voice_text ---> | LLM 任務規劃器 → 結構化 JSON 計畫  |
| 鏡頭 → 髒污偵測（YOLO 權重）  | -- dirt_detected --> | 共享地圖：已知髒污、障礙、禁區      |
| 障礙偵測                     | - obstacle_detected> | 任務黑板：建立 / 相依 / 分派任務    |
| A* 自主導航、清潔、夾取       | <---- assign ------- | 成本派工、電量水量管理、巡邏        |
+------------------------------+ <-- cancel / dock -- +-----------------------------------+
```

- **LLM 只做規劃，不輸出馬達指令**：中控台把語音指令轉成任務；機器人自己用 A* 在共享地圖上規劃路徑。
- **語音在機器人端轉文字**：每台機器人有麥克風和輕量 ASR，只把文字和自己所在的區域傳回中控台。所以「這裡有人打翻飲料」會清理那台機器人所在的區域。
- **髒污偵測用另一份權重**：偵測器與 LLM 分開，分成乾垃圾、液體、混合髒污三類。遠距離容易誤判，靠近後會複判並修正。

## 分工流程

| 情境 | 中控台怎麼處理 |
|---|---|
| 乾垃圾 | 派掃地機 |
| 液體 | 派拖地機 |
| 混合髒污（飲料連碎片） | 先派掃地機掃起碎片，留下的液體殘留自動轉給拖地機 |
| 「先清理生鮮區…最後再掃收銀區」 | 區域任務依序執行，拖地任務等掃地完成才開始 |
| 發現紙箱、推車、棧板 | 標記為禁區，派障礙排除機夾起並搬到倉儲區，搬走後解除禁區 |
| 發現電線 | 不可移動（可能正在使用），只標記禁區並在周圍加上避讓範圍，所有清潔機器人繞開；障礙排除機不會去搬 |
| 兩台機器人搶同一格 | 格子預約：路權高的先走，路權低的等待後改走替代路徑 |
| 電量 < 20% 或水箱 < 10% | 叫回充電站，未完成的任務放回任務黑板，由其他機器接手 |
| 沒有任務時 | 掃地機輪流巡邏各區，邊巡邊掃、邊發現髒污 |

## 每台機器人獨立語音控制

指令是對「某一台」機器人說的，由那台機器人優先執行：

| 對誰說 | 說了什麼 | 結果 |
|---|---|---|
| S2（掃地機） | 「去掃貨架A區」 | S2 自己掃整區，會中斷手上的巡邏或定點工作 |
| M1（拖地機） | 「去掃收銀區」 | M1 回答自己是拖地機，掃地交給掃地機（兩台分段同時做） |
| S1 | 「這裡有人打翻飲料，處理一下」 | S1 掃起碎片，拖地交給拖地機；「這裡」指 S1 所在的區域 |
| 任一台 | 「停下來」／「繼續工作」 | 只有這台原地停下；手上的任務保留，說繼續後接回來 |
| 任一台 | 「回充電站」 | 只有這台回去充電並待命 |
| 任一台 | 「全部回充電站待命」「大家繼續工作」 | 句子裡有「全部、大家、所有」時才影響整個機隊 |

每台機器人都會用對話回覆它聽到什麼、接下來要做什麼，對話紀錄依機器人分開顯示。

## 模型可抽換（config.toml）

| 模組 | 預設 | 換成真的模型 |
|---|---|---|
| 任務規劃 `[planner]` | `rule`：關鍵字規則 | `backend = "ollama"`、`model = "gemma3:4b"`（任何 Ollama 模型）；LLM 失敗時自動退回規則規劃器 |
| 語音轉文字 `[asr]` | `text`：儀表板輸入的句子當成收音結果 | `backend = "whisper"`（需 `pip install faster-whisper`） |
| 髒污偵測 `[detector]` | `sim`：讀真實髒污並加入誤判 | `backend = "yolo"` 的介面已預留；2D 模擬沒有鏡頭影像，要接 Gazebo / Webots 或實拍影像才能真正推論 |

機隊組成、初始電量、通訊延遲也在 `config.toml` 裡設定。

## 儀表板操作

- **對機器人說話**：上方四個按鈕切換對象（也可以按數字鍵 1–4，或直接點地圖上的機器人），被選中的機器人在地圖上有白色圈。輸入句子或按下方的範例句；🎤 按鈕用瀏覽器的語音辨識代替機器人的麥克風（Chrome 可用，會經過 Google 的語音服務；不想外傳就用打字）。
- **點地圖放置**：選好乾垃圾、液體、紙箱、電線等，再點地圖，測試機器人如何應變。
- **半透明物件**：真實存在、但還沒有機器人看到的東西。可以觀察「發現 → 回報 → 派工」的過程。
- **日誌**：每一筆都分類（語音、LLM、派工、辨識、障礙、電量、衝突），可以篩選。

## Webots 3D 版本（`webots/`）

需要 Webots R2025b（目前用 nightly 版，R2025a 在 macOS 27 無法啟動）。

```bash
python3 webots/make_world.py   # 由 sim/world.py 的地圖產生兩個場景
```

| 場景 | 內容 |
|---|---|
| `webots/worlds/supermarket_console.wbt` | **接上中控台**：FLEET 監督控制器執行同一套中控台、LLM 規劃與機器人邏輯，3D 機器人、髒污、障礙物即時同步。儀表板在 http://127.0.0.1:8781，語音指令、任務黑板、日誌都在那裡操作 |
| `webots/worlds/supermarket.wbt` | 第一階段：每台機器人用自己的控制器各自清潔，沒有中控台 |

目前 3D 機器人跟著中控台的格子位置移動（數位分身）；之後可改成由輪子馬達實際行駛、用光達與鏡頭做感知。

### 機器人鏡頭畫面

開 `supermarket_console.wbt` 時，儀表板右上會多出「鏡頭畫面」：大畫面是目前對話對象的第一人稱鏡頭（每秒 5 張），下方是其他機器人的縮圖（每秒 1 張，可關掉）。

- 每台機器人跑 `controllers/camera_feed`，鏡頭 320×240、視角約 69°，畫面存成 `webots/.frames/<機器人>.jpg`，儀表板從 `/api/camera/<機器人>.jpg` 讀取。
- **沒人看就不渲染**：儀表板每次取畫面時會告訴那台機器人要幾張/秒；超過 3 秒沒人來取，那台的鏡頭就關閉。
- 實測（M5，即時模式）：開著 4 支鏡頭畫面和完全不看，整體 CPU 都約 24%，主要是 Webots 的 3D 主視窗在耗；快轉模式下開 4 支鏡頭會從 9.5 倍速降到 7.8 倍速，每秒 5 張和 15 張差不多。

### YOLO 髒污偵測（框在鏡頭畫面上）

YOLO 在獨立的 Python 環境 `.venv-yolo` 裡跑（torch 太大，不放進 Webots 控制器）。

**已附訓練好的權重 `weights/dirt_yolov8n.pt`**（驗證集 mAP50 0.95），只要建環境就能直接用，不必重做資料集和訓練：

```bash
python3 -m venv .venv-yolo && .venv-yolo/bin/pip install ultralytics
```

想自己重新產生資料集、重新訓練時：

```bash
python3 -m venv .venv-yolo && .venv-yolo/bin/pip install ultralytics
python3 webots/make_world.py
# 1. 產生標註資料：開 dirt_dataset.wbt，相機機器人在賣場裡隨機撒髒污、拍照、自動標框（約 20 分鐘）
/Applications/Webots.app/Contents/MacOS/webots --mode=fast --minimize --batch webots/worlds/dirt_dataset.wbt
# 2. 訓練 YOLOv8n，結果存到 weights/dirt_yolov8n.pt
.venv-yolo/bin/python webots/train_yolo.py
```

之後開 `supermarket_console.wbt`，`fleet_bridge` 看到權重檔就會自動啟動 `webots/yolo_worker.py`：它對每一張新的鏡頭畫面跑 YOLO，儀表板的主鏡頭畫面上就會框出乾垃圾、液體、混合髒污和信心度，右下角顯示偵測數量和推論時間。

- **標註怎麼來**：每塊髒污是一個 Solid，帶有自己的 recognition 顏色；鏡頭的 Recognition 分割影像會把它畫成那個顏色，取那些像素的範圍就是框。被貨架擋住的部分不會算進去。
- **髒污外觀有隨機變化**：乾垃圾是幾片大小顏色不同的紙屑，液體是半透明、反光的水漬，混合髒污是有顏色的飲料加玻璃碎片，位置、旋轉、大小每次都不一樣。
- 目前偵測結果只畫在畫面上；中控台派工仍用模擬偵測器。要讓 YOLO 的結果直接變成派工，下一步是把畫面上的框換算回地板上的格子。
